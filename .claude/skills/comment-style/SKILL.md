# 주석 스타일

## 기본값: 주석 안 씀

코드가 이미 보여주는 걸 설명하는 주석은 쓰지 않는다. WHY가 정말 비직관적일 때만(숨은 제약, 미묘한 불변조건, 특정 버그 우회 등) 한 줄 추가를 고려한다.

## 쓰기로 했다면

- 마침표(.) 금지
- `~한다`, `~된다`, `~않는다` 등 동사 종결형 금지
- 명사형(~처리, ~조회, ~반환) 또는 `~ㅁ` 종결형(`~함`, `~됨`, `~없음`) 사용
- 2줄 넘게 늘어놓지 않기
- 테스트 메서드 이름(백틱 문자열, `fun \`~한다\`()`)에는 적용 안 함 — 주석에만 적용

## 체크 방법

주석을 쓴 직후 그 줄만 다시 보고 위 규칙에 맞는지 확인한다. 이미 있던 다른 파일·다른 주석까지 훑어보는 별도 검증 패스는 하지 않는다 — 토큰 낭비다. 지금 건드리는 줄만 본다.

## 예시

- 나쁨: `// 텍스트 판정은 LLM이 분류하기 전이라 category가 없다 — 음식명 완전일치로만 매칭한다.`
- 좋음(정말 필요하면): `// 텍스트 판정은 LLM 분류 전이라 category 없음 — 음식명 완전일치로만 매칭`
- 더 좋음: 주석 없이 코드만
