# ADR-0002: 이해하며 구현하기 위해 파일마다 코드를 보여 주고 설명으로 확인한다

- 상태: 채택
- 날짜: 2026-11-26

## 배경

rate limiter(#45)를 구현하면서, 코드를 대신 써 주는 데서 끝나지 않고 작성자가 설계와 코드를 직접 이해하고 설명할 수 있어야 한다는 요구가 있었다. 낯선 라이브러리(Bucket4j)와 필터 순서처럼 틀리기 쉬운 부분이 많았다.

## 결정

- 구현 전에 라이브러리 설명과 설계 후보를 먼저 나열하고, 선택은 작성자가 한다. 선택이 바뀌면 이유와 함께 결정 로그(`decisions.log`)와 ADR에 남긴다.
- 파일을 하나씩 작성하고, 파일마다 코드를 보여 준 뒤 작성자가 본인 말로 설명한다. 빠졌거나 틀린 부분만 짚고 다음 파일로 간다. 질문을 한꺼번에 많이 던지지 않는다.
- 확인하지 못한 것(예: Railway 헤더, 라이브러리 최신 버전)은 확인했다고 쓰지 않고 한계로 적는다.

## 결과

- 파일 단위로 진행하므로 한 번에 끝내는 것보다 느리지만, 설계 오류(예: 필터에서 던진 예외는 `@RestControllerAdvice`가 못 잡는다는 점, 프록시 뒤 IP 문제)를 구현 전에 잡을 수 있었다.
- 이 방식을 계속 쓸지는 작성자가 정한다. 필요 없어지면 이 ADR을 폐기 상태로 바꾼다.
